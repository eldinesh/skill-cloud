# Meridian Health: Requests platform

Thursday brief for the Building Koru 3.0 hackathon. Every team gets the same pack.

Meridian Health is a made-up client. Everything in this pack is invented. None of it is client data.

## What's in the pack

| File | What it is |
| --- | --- |
| 01-client-brief.md | The brief Meridian sent to Koru |
| 02-prd.md | Meridian's product requirements document, written by their product owner |
| 03-kickoff-transcript.md | Transcript of the Koru and Meridian kick-off call |
| 04-po-tech-transcript.md | Transcript of a call between Meridian's product owner and engineering lead |
| 05-user-interviews.md | Four user interview transcripts |
| 06-research-synthesis.md | A research synthesis from an earlier round of discovery |
| 07-analytics-export.csv | An export from Meridian's current request tool and reporting |
| 07-analytics-notes.md | What each column in the export means |
| 08-support-tickets.md | Recent support tickets and complaints about the current tool |
| 09-tech-constraints-and-components.md | Engineering notes on systems, APIs and the existing component library |
| 10-slack-thread.md | A Slack thread between Meridian's product owner and dev lead about the last release |
| 11-system-architecture.md | How systems connect today, as a Mermaid diagram, with where new things could plug in |
| 13-unitdesk-current-platform.html | A clickable mock of UnitDesk, the current tool, as staff see it today. Open it in a browser. |
| 12-meridian-ui/ | Meridian's existing component library: tokens, component markup and a gallery page |

## How to use it

- Run it through your own playbook, starting with Frame.
- The documents don't all agree. That's on purpose, and it's how real projects arrive. Part of the job is spotting where they disagree and deciding what to believe.
- If something is unclear, ask an organiser. They'll answer as the client or play a user.
- 14:30 Thursday is a hard stop.
